# model-studio

きんぽよアプリの**回数カウント用モデルを作るためのアプリ群**。製品アプリ本体（`kinpoyo/`）とは別系統で、
学習データの収集からモデルの学習・精度チェックまでを担う。ここで作ったモデルを製品側が利用する。

## 構成

| ディレクトリ | 役割 |
|---|---|
| `frontend/` | 収集アプリ（Expo / スマホ）。端末のフォトライブラリから動画を選び、区間をトリムして学習データ（セッション）としてアップロードする。 |
| `analyzer/` | 分析アプリ（Expo / PC ブラウザでも動作）。セッションの関節角度を分析し、正解回数を登録し、モデルを学習させ、`/check` 画面で任意の動画に対する回数カウントの精度を検証する。 |
| `backend/` | FastAPI。姿勢推定（MediaPipe）、分析、モデルの学習・保存、回数カウントを提供する。Azure App Service にデプロイ（`backend/deploy.ps1`）。 |

## モデル作成の流れ

1. `frontend/` で端末内の動画を選び、学習データとしてアップロードする。
2. `analyzer/` でセッションを分析し、**正解回数**（実際に何回やったか）を登録する。
3. タグ単位でモデルを学習させる（`POST /tags/{id}/build-model`）。学習の実体はニューラルネットではなく、
   正解回数を最も再現できる状態機械の閾値・主役関節・1レップの標準カーブ・受理ゲートの較正。
4. `analyzer/` の `/check` 画面で別の動画を流し、回数が合うか検証する。合わなければ 1〜3 を繰り返す。

## 関節角度の座標系（重要）

角度はすべて MediaPipe の **world ランドマーク**（腰の中点を原点とする、メートル単位の実3D座標）から計算する。
3点で決まる角度は座標系の回転・平行移動に対して不変なので、**カメラをどこに置いても同じ値**になる。

画像座標（`pose_landmarks`）から角度を出してはいけない。x は画像幅・y は画像高さで別々に正規化されるため
アスペクト比の分だけ歪み、同じ姿勢でも縦動画と横動画で 10 度以上ずれる。z はさらに別スケールで、混ぜた内積は
カメラと動画サイズに依存した無意味な角度になる。画像座標は骨格の描画にのみ使う（`landmark_mean`）。

`FrameSample` は両方を保存する（`pose_landmarks` = 描画用 / `pose_world_landmarks` = 角度用）。

**world 移行前の旧データは使えない。** 動画は処理後に削除されるため world 座標を後から復元できない。
旧セッションは `RecordingSession.pose_space = 'image'` として区別され、分析・学習から弾かれる
（analyzer のセッション選択画面で「要再取込」と表示される）。同じ動画を選び直して再アップロードすれば `'world'` になる。
旧モデル（`config_json` に `poseSpace` が無い）も受理ゲートの絶対角度が噛み合わないため、カウント時に弾かれる。再学習が必要。

## 開発

- `backend/`: `pip install -r backend/requirements.txt` → `uvicorn main:app --reload`
- `frontend/` / `analyzer/`: `npm install` → `npx expo start`（analyzer は `--web` で PC ブラウザ）
- バックエンドのデプロイ先は `analyzer/constants/api.ts` の `API_URL` を参照。
